# Quorum Read Repair Bug Design

## Goal

Add a realistic distributed-system bug package that stresses both global message
delivery choices and local goroutine scheduling choices. The package should be
easy to run with the current orchestrator infrastructure, should not depend on
`time.Sleep` or timer-based delay injection, and should produce a bug that is
more interesting than a single global message reorder.

The proposed package is `bugs/quorum-read-repair`.

## System

The system is a small Dynamo-style quorum KV store with three replicas and two
clients.

Each replica stores a set of sibling values per key. Every value carries a
simplified vector clock:

```go
type VersionedValue struct {
	Value string
	Clock map[string]int
}
```

Clients issue writes to all replicas and wait for `W=2` acknowledgements. Reads
query all replicas and wait for `R=2` responses. A read coordinator merges the
responses it receives, returns the chosen value set, and sends read-repair
messages to replicas that appear stale.

Correct behavior is sibling preservation: if two vector clocks are concurrent,
both values must survive convergence. For the core scenario, concurrent writes
`A` and `B` should converge to the sibling set `{A, B}` on every replica.

## Replica Goroutines

Each replica should run several local goroutines so that local scheduling is a
meaningful part of the search space:

- `router`: reads delivered network messages and dispatches them by kind.
- `applyLoop`: serializes normal client writes from an apply queue.
- `repairLoop`: applies read-repair messages from a separate repair queue.
- per-request coordinator goroutines for quorum reads and writes.

The separate normal-write and repair queues are intentional. They model a common
implementation pattern where repair traffic is handled by a background worker,
and they create local interleavings that can affect final state.

## Messages

The transport should follow existing bug package conventions and use ordinary
orchestrator-controlled sends. It should not inject sleeps or artificial delayed
messages.

Message kinds:

- `Put`
- `PutAck`
- `Get`
- `GetResp`
- `Repair`
- `RepairAck`
- `Control` for deterministic workload start barriers only

All traffic should be generated by normal client operations and read repair.
Control messages must not encode the failing schedule, delay protocol traffic,
or inject synthetic state.

## Deliberate Bug

The bug is in read repair. The correct merge rule is:

- if one clock dominates another, keep the dominated value out
- if clocks are concurrent, keep both values as siblings

The buggy repair path collapses concurrent siblings to a single winner. It uses
a scalar score such as the sum of vector-clock entries, with arrival order as a
tie-breaker:

```go
func buggyRepairMerge(local, incoming []VersionedValue) []VersionedValue {
	return []VersionedValue{pickSingleWinner(local, incoming)}
}
```

Normal client writes should use the correct sibling-preserving merge. This makes
the bug specifically about the interaction between read repair and local
application order, not about all writes being trivially wrong.

## Failure Shape

The workload starts three replicas `R1`, `R2`, `R3` and two clients `C1`, `C2`.

1. `C1` writes `x=A` with clock `{C1:1}` to all replicas and completes after
   two acknowledgements.
2. `C2` writes `x=B` with clock `{C2:1}` to all replicas and completes after
   two acknowledgements.
3. A read queries all replicas and completes after two responses.
4. The read coordinator sends repairs based on the possibly incomplete sibling
   set it observed.
5. The test waits for all client work and observable repair traffic to drain,
   then checks every replica's final sibling set for `x`.

The intended invariant is that all replicas converge to `{A, B}`. A failure is
any replica losing one sibling or replicas ending with different sibling sets.

## Required Interleaving Character

The bug should require mixed exploration:

- A global delivery choice determines which write acknowledgements and read
  responses form the observed quorums.
- A local scheduling choice determines whether a replica's `repairLoop` applies
  a buggy repair before or after its `applyLoop` processes a concurrent normal
  write.

The canonical FIFO run should pass. A global-only search should be weaker than a
global-plus-local search. A targeted `FindBug` test may choose among pending
global and local alternatives, but it must not use sleeps, timer delays, or
synthetic message injection.

The expected bug depth should be at least two meaningful non-default choices in
the combined trace, with at least one global choice and at least one local
choice.

## Tests

Add tests similar to the existing `bugs/ra-*` packages:

- `TestQuorumReadRepair_FIFOPasses`: canonical FIFO run converges to `{A, B}`.
- `TestQuorumReadRepair_ExploreGlobalOnly`: runs bounded global exploration and
  logs whether the bug is found.
- `TestQuorumReadRepair_ExploreAll`: runs combined global/local exploration and
  should find the bug.
- `TestQuorumReadRepair_FindBug`: targeted scheduler proving the bug is
  reachable without sleep or artificial delay.

Add benchmarks following the existing `TestBench_*` pattern:

- CHESS global-only
- CHESS global plus local
- PCT depth 2
- PCT depth 3
- Random

The benchmark maximum run count can start around 200 and be adjusted after the
first implementation shows the size of the trace space.

## Files

Planned package files:

- `transport.go`: orchestrator transport and message definitions.
- `store.go`: replica state, vector-clock merge helpers, normal apply loop, and
  buggy repair loop.
- `client.go`: quorum read/write client.
- `scenario.go`: cluster setup and workload construction.
- `bug_demo_test.go`: correctness and exploration tests.
- `bench_test.go`: benchmark-chart compatible exploration tests.
- `BUG.md`: short explanation of the bug, failure sequence, and why no sleeps
  are required.

## Scope Limits

This package should not model crashes, partitions, leases, real timeouts,
anti-entropy timers, or membership changes. The first implementation keeps all
concurrency event-driven through ordinary messages and local goroutines.
